# Content-Engine — موتور محتوا و پادکست

موتورِ تک‌فایلیِ Google Apps Script که هر روز دو پادکستِ فارسی می‌سازد:
**«از همه جا از همه رنگ»** (متنوع، انتشار ۷:۰۰ دبی) و **«درس‌نامه»** (تخصصی، ۸:۰۰).
موتور پنج Google Sheet را **فقط می‌خواند** و خروجی (صدا/متن/وضعیت) را در پوشهٔ
OUTPUT درایو می‌نویسد.

کدِ مستقر یک فایل است: **`engine.gs`** در ریشهٔ ریپو — که از ۲۳ بخشِ داخلِ `src/`
با `tools/build.js` سرِ هم می‌شود. نسخه در `src/00_Config.gs` (کلیدِ `CODE_VERSION`) است.

---

## چرخهٔ خودکارِ به‌روزرسانی (منبع: همین ریپو)

از نسخهٔ **۵٫۱۲**، منبعِ حقیقتِ کد **همین ریپوی گیت‌هاب** است. هر شب ۲:۳۰ دبی:

1. موتور `manifest.json` را از raw گیت‌هاب می‌خواند.
2. اگر `version`ِ آن از نسخهٔ در حالِ اجرا بالاتر بود، `engine.gs` را می‌گیرد،
   **اثرانگشتِ SHA-256 + نسخهٔ داخلِ فایل + توابعِ ضروری + کامپایلرِ گوگل** را
   می‌سنجد، با Apps Script API خودش را عوض می‌کند، `afterCodeSwap` تریگرها را
   دوباره مسلح می‌کند و تلگرام/ایمیل خبر می‌دهد.
3. یک کپیِ کامل هم در پوشهٔ «کدها»ی درایو می‌ماند (بایگانی + پشتیبان).

بازگشتِ اضطراری: در `src/00_Config.gs` مقدارِ `CODE_SOURCE` را `'drive'` کن.

## قانونِ کارِ تغییرات (مهم)

- **تغییرات خودکار push می‌شوند.** هر کس (کلاد یا ناظرِ خودکار) تغییری بدهد،
  خودش پس از سبز شدنِ همهٔ آزمون‌ها `git push` می‌کند — **هرگز منتظرِ push دستیِ
  کاربر نمی‌ماند و فایل را دستی تحویل نمی‌دهد.**
- **هر تغییر در همین README ثبت می‌شود** — یک ردیفِ تازه در «تاریخچهٔ نسخه‌ها».

## ساختارِ ریپو

```
engine.gs · manifest.json · README.md · CLAUDE.md   ← باید در ریشه بمانند
src/                 ۲۳ بخشِ شماره‌دار — منبعِ حقیقتِ کد
tools/               build.js + build_header.txt
tests/               ۲۷ آزمونِ run_*.js
tests/lib/           root.js (لنگرِ مسیر) · mock.js (مقلدِ GAS) · probe_r4_lib.js
tests/fixtures/      newsheets.json · videos.jsonl · photos.jsonl
docs/                monitor_prompt_current.txt
archive/             فقط تاریخی — هرگز منبعِ build/test نیست
```

آن چهار فایلِ ریشه جابه‌جا نمی‌شوند: موتور `engine.gs` و `manifest.json` را از
همان آدرسِ rawِ ریشه می‌خواند. `tools/build.js` هم هر جا صدایش بزنی، خروجی را در
ریشه می‌نویسد.

## ساخت و آزمون

```sh
node tools/build.js                                        # -> engine.gsِ ریشه
for f in tests/run_*.js; do node "$f" || echo "FAIL $f"; done   # همه باید سبز شوند
```

هر آزمون اول `tests/lib/root.js` را صدا می‌زند که cwd را روی ریشه می‌گذارد، پس
آزمون‌ها از هر پوشه‌ای اجرا می‌شوند.

## دستِ‌دادنِ انتشار (برای هر تغییرِ کد)

1. ویرایش در `src/` (همهٔ تغییرهای به‌هم‌وابسته با هم).
2. نسخهٔ تازه = `max(در حالِ اجرا، نسخهٔ ریپو) + ۰٫۱`؛ در `src/00_Config.gs` دقیقاً
   همان را بگذار (نسخهٔ داخلِ فایل باید با `manifest` یکی باشد).
3. `node tools/build.js` → `engine.gs`ِ ریشه.
4. همهٔ `tests/run_*.js` سبز.
5. `sha256sum engine.gs`.
6. `manifest.json` را به‌روز کن: `{version, codeFile, sha256, releasedAt, summary, fixes, sourceReportIds}`.
7. یک ردیف به «تاریخچهٔ نسخه‌ها»ی همین README اضافه کن.
8. `git add -A && git commit && git push origin main` — **خودکار، بی‌انتظار.**

جزئیاتِ کامل و قواعدِ مطلق (فقط‌خواندنی‌بودنِ شیت‌ها، پوشهٔ پشتیبان و …) در
[`CLAUDE.md`](./CLAUDE.md).
